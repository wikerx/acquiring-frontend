# Vexra 前端开发规范

## 1. 适用范围

本规范适用于 `admin-system`、`merchant-portal`、`hosted-checkout` 和 `@acquiring/shared`。根及应用目录下的 `AGENTS.md` 是 AI 开发时自动生效的约束，本文件说明长期维护原则。

历史菜单和表格整改方案用于追溯背景，不再要求每次前端任务全文加载。

## 2. 技术基线

- Vue 3、TypeScript strict、Vite、Pinia、Vue Router、Axios、Vue I18n；
- Admin 和 Merchant 使用 Element Plus；
- Hosted Checkout 延续现有轻量样式和 Tailwind 配置；
- 当前执行脚本以 npm workspace 和 `package-lock.json` 为准；
- 未确认前不得升级依赖、切换包管理器或引入新的 UI 框架。

仓库同时保留 pnpm 文件。普通开发不得同时修改 npm 与 pnpm 两套锁文件；包管理策略调整必须单独评审。

## 3. 后端契约优先

新增或修改页面前必须确认：

- 接口路径、方法、请求和响应；
- 枚举、状态、错误码和金额语义；
- 菜单、按钮和字段权限；
- 分页、排序和筛选规则；
- 时间、币种和敏感字段格式。

禁止为了页面展示伪造接口、字段、状态、权限、交易结果和业务数据。后端能力不存在时，使用明确的待接入/不可用状态，不得用静态数据伪装完成。

## 4. 分层与复用

- `api` 负责请求封装和契约类型；
- Store 管理跨页面、会话或持久 UI 状态，不承载后端业务规则；
- View 组织页面用例，复杂可复用交互下沉为组件或 composable；
- 通用类型、常量、请求能力优先复用 `@acquiring/shared`；
- 应用专属组件保留在应用内，不因两个相似页面就过早跨应用抽象。

不得绕过统一请求拦截器、路由守卫、权限指令、错误处理或登录状态。

## 5. 表格

标准列表页使用应用自己的 `StandardTable`，并提供稳定、具有应用命名空间的 `table-key`。

必须保持：

- 字段过多时在表格内部横向滚动；
- 列宽、显隐、顺序和重置兼容历史缓存；
- 固定业务标识、选择和操作列按业务要求不可隐藏；
- 编辑列只是展示偏好，不能代替字段权限；
- Admin 与 Merchant 的偏好键隔离；
- 新增、删除、重命名列时处理旧缓存。

弹窗选择表、诊断表、少量字段预览表、虚拟表格等可不使用列偏好，但应保持现有公共样式和交互。

## 6. 表单与对话框

- 校验规则来自确认的业务契约，错误提示可理解且使用 i18n；
- 提交期间防止重复操作，并提供明确加载和失败恢复；
- 全局 `.dialog-footer` 居中，主操作在取消之前；
- 详情对话框只有关闭操作时保持居中；
- 关闭、取消、路由离开时按数据敏感性清理临时状态；
- 不在前端自行发明审批、金额、状态机或权限判断。

## 7. 菜单、路由与权限

- 菜单和可访问路由由真实后端菜单、角色和权限驱动；
- 侧边与顶部模式使用同一份权威菜单树；
- 多级菜单、页签、面包屑、高亮和页面权限保持一致；
- 按钮隐藏、列隐藏和路由拦截不能替代服务端授权；
- Profile 入口位于用户菜单，并使用现有会话和接口。

禁止回退到静态业务菜单、占位页面或虚假业务指标。

## 8. 国际化、时间和金额

- 用户可见的按钮、标题、状态、表头、校验、空状态和错误提示使用 i18n；
- 新增 key 同步维护项目支持的语言；
- 具体时间复用 `BaseDateTime` 或共享格式化能力，不用 `substring` 截断；
- 金额按接口提供的币种、符号、精度和符号位展示；
- JavaScript 浮点数不得用于资金决策或精确金额推导。

### 8.1 交易类型、支付方式与业务状态的统一展示

交易类型复用 `TransactionTypeDisplay`，支付方式复用 `PaymentMethodDisplay` /
`PaymentLogoGroup`，交易结果复用 `TransactionStatusDisplay`。勾兑、对账、交易结算三个业务域
统一使用 `TransactionStageStatusDisplay` 和 `TransactionStageStatusSelect`，不得在业务页面
重新手写普通标签、颜色或图标映射。该约束覆盖管理端和商户端的普通下拉、可搜索筛选下拉、
选中值、列表单元格、详情抽屉、财务摘要和明细。

共用选择框只接收页面已有字典选项，不自行发起请求；字典的启停、顺序、文案与选项范围继续
沿用既有契约。相同字典的并发读取由字典 API 合并，读取失败不能伪装成成功。展示与筛选
分离：选择框始终提交原始 `value`，清空返回空字符串；禁止把资源 key、中文文字或视觉语义
写回接口、数据库或状态机。

#### 状态与资源映射

资源来自用户提供的 V5 状态扩展包，13 个 SVG 存放于
`packages/shared/src/assets/transaction-icons/stages`。业务域和状态码必须同时匹配，不能只凭
`FAILED` 或“不一致”等通用文字判断含义。

| 业务域 | 接口状态码 | SVG 资源 | 视觉语义 |
| --- | --- | --- | --- |
| 勾兑 | `NOT_REQUIRED` | `MATCH_NOT_REQUIRED` | 中性、减号 |
| 勾兑 | `PENDING` | `MATCH_UNMATCHED` | 中性、内环 |
| 勾兑 | `REVIEW_REQUIRED` | `MATCH_PENDING_REVIEW` | 待复核、人形 |
| 勾兑 | `MATCHED` | `MATCH_SUCCESS` | 成功、对勾 |
| 勾兑 | `MISMATCHED` | `MATCH_MISMATCH` | 业务差异、不等号 |
| 勾兑 | `FAILED` | `MATCH_FAILED` | 执行失败、叉号 |
| 对账 | `NOT_RECONCILED` | `RECON_UNRECONCILED` | 中性、内环 |
| 对账 | `RECONCILED` | `RECON_RECONCILED` | 成功、对勾 |
| 对账 | `MISMATCHED` | `RECON_MISMATCH` | 业务差异、不等号 |
| 交易结算 | `NOT_SETTLED` | `SETTLE_UNSETTLED` | 中性、内环 |
| 交易结算 | `SETTLING` | `SETTLE_PROCESSING` | 处理中、循环箭头 |
| 交易结算 | `SETTLED` | `SETTLE_SETTLED` | 成功、对勾 |
| 交易结算 | `FAILED` | `SETTLE_FAILED` | 执行失败、叉号 |

不一致与失败可以同属红色，但必须保留独立图标、状态码与筛选项；“无需勾兑”不得标为成功绿。
未知状态保留接口值或字典文案，以无图标中性样式降级；空值显示 `-`，不得猜成成功或失败。
结算批次、审批、付款、入账、清分、风险审核等状态有各自契约，不能因为文字相似就套用本表。

#### 视觉与交互规格

- 标签高度 24px、圆角 6px、左右内边距 8px；图文间距 5px。
- SVG 画布使用 20px 容器，资源内可视圆直径约 16px；文字 12px、字重 500。
- 成功背景/文案为 `#F0FDF4` / `#166534`；失败与差异为 `#FEF2F2` / `#B91C1C`。
- 处理中背景/文案为 `#EFF6FF` / `#1D4ED8`；待复核为 `#FFFBEB` / `#92400E`；
  中性为 `#F1F5F9` / `#475569`。图标颜色与符号使用资源包原始 SVG。
- 下拉选项与选中值复用同一标签；搜索匹配字典文字，保留清空、禁用和键盘操作。
- 列表沿用表格对齐规则；长文案省略但保留完整标题；图标为装饰，辅助技术读取完整状态文字。
- 中英文由现有字典与 i18n 提供，组件不硬编码业务文案；兼容当前布局与主题，不覆盖全局配色。

执行 `npm run test:governance:transaction-status` 检查接入约束和资产；该检查已加入双端构建。
改动需验证 13 个状态、未知/空值、SVG 加载、下拉搜索与选中值、清空、原始查询码、详情展示、
语言切换，以及字典并发读取和失败重试。不得仅凭构建成功声明页面验收完成。

## 9. 安全与隐私

禁止在控制台、URL、浏览器存储、埋点、错误信息、Fixture、截图中记录：

- PAN、CVV；
- JWT、Token、API Key、商户密钥；
- 解密报文或完整支付响应；
- 未脱敏证件、银行卡、手机号和邮箱；
- 其他商户或无权限字段的数据。

外部链接、iframe、重定向、返回地址和 HTML 内容使用现有来源校验和安全渲染机制。

## 10. Hosted Checkout

Checkout 必须覆盖商户与金额确认、支付方式、输入校验、处理中、挑战/跳转、成功、拒绝、待定、未知、技术错误和恢复路径。

HTTP 成功不等于支付成功。未知结果不得显示为失败后自动重试，也不得显示为成功。桌面和移动端均需验证布局、键盘、焦点、自动填充、重复点击和敏感数据生命周期。

## 11. 验证

至少执行受影响应用的：

```bash
npm run lint
npm run typecheck
npm run build:<admin|merchant|checkout>
```

共享包变更还需验证共享类型和所有受影响应用。页面布局或交互变更使用真实浏览器检查桌面/移动视口、控制台、网络、权限、i18n、文本溢出、遮挡和主要工作流。

`npm run lint` 是统一静态检查入口。不得使用未审查的自动修复掩盖问题，也不得为了通过检查降低规则、扩大忽略范围或跳过受影响代码。

## 12. 图片与文件上传组件

图片上传也遵循“上传与下载·统一组件标准（FILE COMPONENTS / V1）”。使用共享 `ImagePicker`，不要为渠道 Logo、个人头像等页面另做大占位框与独立按钮组合。视觉沿用蓝白灰、8–10px 圆角和浅色虚线拖拽区，按钮高度 36px，选择、更换和移除操作统一放在上传区域操作栏。导入场景继续复用 `BaseImportDialog`，两者保持同一视觉语言。

- 未选择、已选择待上传、校验/保存中、已上传、移除待保存和失败状态均以图标、文字及明确下一步反馈；本地预览不表示文件已上传或已通过服务端扫描。
- 已选择时展示缩略图、文件名和大小，支持点击预览；取消表单不产生服务器文件。
- 图片白名单保持 PNG/JPEG、单张最多 2 MiB。校验真实文件头、扩展名与 MIME；伪装为 `.png` 的 WebP 应明确提示真实格式，不提示为大小超限，不放宽白名单。
- 后端仍检查权限、格式/大小及 ClamAV，所有验证通过后才写入私有存储。前端提示不能代替后端安全控制。

渠道身份展示复用 `ChannelIdentity` / `ChannelDisplay`：有 Logo 时等比例完整显示，并在悬停或键盘聚焦时显示当前语言名称；缺图、已删除或读取失败时沿用该字段原文字。列表图片区域固定 72×28px，详情固定 96×36px，加载中预留同尺寸区域，不按原始分辨率撑开单元格。显式的渠道编码、中英文名称资料字段继续保留其原始含义。元数据查询合并为每批最多 100 个引用，私有图片按登录主体、页面权限范围、渠道与版本进行有界内存复用，不写入本地存储。

渠道展示回归运行 `npm run test:channel-presentation` 和 `npm run test:e2e:channel`，覆盖批量与缓存边界、各接入页面列表/详情、桌面与窄屏、语言切换、键盘预览、缺图和读取失败回退；交易页面同时运行既有字典加载、状态展示及操作权限回归。
