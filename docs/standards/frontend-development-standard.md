# Vexra 前端开发规范

## 1. 适用范围

本规范适用于 `admin-system`、`merchant-portal`、`hosted-checkout` 和 `@acquiring/shared`。根及应用目录下的 `AGENTS.md` 是 AI 开发时自动生效的约束，本文件说明长期维护原则。

历史菜单和表格整改方案用于追溯背景，不再要求每次前端任务全文加载。

## 2. 技术基线

- Vue 3、TypeScript strict、Vite、Pinia、Vue Router、Axios、Vue I18n；
- Admin 和 Merchant 使用 Element Plus；
- Hosted Checkout 延续现有轻量样式和 Tailwind 配置；
- 当前执行脚本以 npm workspace 和 `package-lock.json` 为准；
- 未确认前不得升级依赖、切换包管理器或引入新的 UI 框架。

仓库同时保留 pnpm 文件。普通开发不得同时修改 npm 与 pnpm 两套锁文件；包管理策略调整必须单独评审。

## 3. 后端契约优先

新增或修改页面前必须确认：

- 接口路径、方法、请求和响应；
- 枚举、状态、错误码和金额语义；
- 菜单、按钮和字段权限；
- 分页、排序和筛选规则；
- 时间、币种和敏感字段格式。

禁止为了页面展示伪造接口、字段、状态、权限、交易结果和业务数据。后端能力不存在时，使用明确的待接入/不可用状态，不得用静态数据伪装完成。

## 4. 分层与复用

- `api` 负责请求封装和契约类型；
- Store 管理跨页面、会话或持久 UI 状态，不承载后端业务规则；
- View 组织页面用例，复杂可复用交互下沉为组件或 composable；
- 通用类型、常量、请求能力优先复用 `@acquiring/shared`；
- 应用专属组件保留在应用内，不因两个相似页面就过早跨应用抽象。

不得绕过统一请求拦截器、路由守卫、权限指令、错误处理或登录状态。

## 5. 表格

标准列表页使用应用自己的 `StandardTable`，并提供稳定、具有应用命名空间的 `table-key`。

必须保持：

- 字段过多时在表格内部横向滚动；
- 列宽、显隐、顺序和重置兼容历史缓存；
- 固定业务标识、选择和操作列按业务要求不可隐藏；
- 编辑列只是展示偏好，不能代替字段权限；
- Admin 与 Merchant 的偏好键隔离；
- 新增、删除、重命名列时处理旧缓存。

弹窗选择表、诊断表、少量字段预览表、虚拟表格等可不使用列偏好，但应保持现有公共样式和交互。

## 6. 表单与对话框

- 校验规则来自确认的业务契约，错误提示可理解且使用 i18n；
- 提交期间防止重复操作，并提供明确加载和失败恢复；
- 全局 `.dialog-footer` 居中，主操作在取消之前；
- 详情对话框只有关闭操作时保持居中；
- 关闭、取消、路由离开时按数据敏感性清理临时状态；
- 不在前端自行发明审批、金额、状态机或权限判断。

## 7. 菜单、路由与权限

- 菜单和可访问路由由真实后端菜单、角色和权限驱动；
- 侧边与顶部模式使用同一份权威菜单树；
- 多级菜单、页签、面包屑、高亮和页面权限保持一致；
- 按钮隐藏、列隐藏和路由拦截不能替代服务端授权；
- Profile 入口位于用户菜单，并使用现有会话和接口。

禁止回退到静态业务菜单、占位页面或虚假业务指标。

## 8. 国际化、时间和金额

- 用户可见的按钮、标题、状态、表头、校验、空状态和错误提示使用 i18n；
- 新增 key 同步维护项目支持的语言；
- 具体时间复用 `BaseDateTime` 或共享格式化能力，不用 `substring` 截断；
- 金额按接口提供的币种、符号、精度和符号位展示；
- JavaScript 浮点数不得用于资金决策或精确金额推导。

## 9. 安全与隐私

禁止在控制台、URL、浏览器存储、埋点、错误信息、Fixture、截图中记录：

- PAN、CVV；
- JWT、Token、API Key、商户密钥；
- 解密报文或完整支付响应；
- 未脱敏证件、银行卡、手机号和邮箱；
- 其他商户或无权限字段的数据。

外部链接、iframe、重定向、返回地址和 HTML 内容使用现有来源校验和安全渲染机制。

## 10. Hosted Checkout

Checkout 必须覆盖商户与金额确认、支付方式、输入校验、处理中、挑战/跳转、成功、拒绝、待定、未知、技术错误和恢复路径。

HTTP 成功不等于支付成功。未知结果不得显示为失败后自动重试，也不得显示为成功。桌面和移动端均需验证布局、键盘、焦点、自动填充、重复点击和敏感数据生命周期。

## 11. 验证

至少执行受影响应用的：

```bash
npm run typecheck
npm run build:<admin|merchant|checkout>
```

共享包变更还需验证共享类型和所有受影响应用。页面布局或交互变更使用真实浏览器检查桌面/移动视口、控制台、网络、权限、i18n、文本溢出、遮挡和主要工作流。

当前没有通用 `lint` 脚本，不得报告 lint 通过。引入 ESLint 属于独立工程变更，需先建立不会一次性阻塞历史代码的基线。
