# 表单提交与文件导出治理规范

## 1. 适用范围

本规范约束管理系统、商户系统和共享前端包中的数据变更请求、文件导出和模板下载。

## 2. 表单提交保护

- 所有 `POST`、`PUT`、`PATCH`、`DELETE` 请求默认启用共享在途去重器；相同方法、地址、参数和请求体在前一请求结束前只能发送一次。
- 页面仍应为主要提交按钮提供 `loading` 或明确的处理中状态。在途去重器是全局兜底，不替代正常交互反馈。
- 只有经过评审、确实允许并发执行的非业务写请求才能设置 `allowDuplicateSubmission`；普通表单、审批、发布、上传、批量操作不得绕过。
- 前端去重只解决同一浏览器会话的并发重复请求。支付、退款、代付、结算、资金调整、审批、发布、回滚、回调、消息消费等 P0/P1 操作必须继续使用服务端稳定 `requestId`、数据库唯一约束和合法状态条件。
- 请求超时或结果未知时不得由前端静默重试资金类操作；应使用原业务请求号查询或重放，由服务端返回第一次结果。
- 新建 Axios 客户端必须接入 `createDuplicateSubmissionGuard`，并在成功和失败路径释放。业务页面不得通过 `fetch`、`XMLHttpRequest` 或直接 `axios.post/put/patch/delete` 绕过受控客户端，也不得自行设置 `allowDuplicateSubmission: true`。`npm run test:governance:submissions` 对客户端、写请求和绕过行为执行门禁检查。

## 3. 下载与导出分类

- 模板中心静态模板、已生成凭证和固定资产继续同步流式下载，不得错误接入异步导出任务。
- 小数据量且有明确上限的导出可以同步处理，但必须保证权限、租户范围和字段范围与列表查询一致。
- 需要大范围查询、聚合或生成大量行的导出必须提交到统一异步下载中心，并携带稳定 `requestId`。
- 异步导出必须冻结创建人、所属系统、商户范围、筛选条件、语言和时区；后台任务分页读取并流式写入私有对象存储。
- 卡 BIN、任务运行日志、交易、退款、结算、资金、费率、基础数据和风控等已接入异步任务的页面不得恢复为浏览器等待同步全量响应。
- 页面不得重新引用遗留同步全量导出 API；Blob 传输必须集中在双端共享下载工具。`npm run test:governance:exports` 对异步任务入口、遗留同步导出引用和 Blob 传输位置执行门禁检查。
- 任务提交、调度领取、失败重试、下载和过期清理必须分别具备持久幂等、版本条件、归属校验和审计记录。

## 4. 验收要求

- 同一表单快速连续点击只产生一个网络写请求。
- 首次请求完成后允许发起下一次合法操作。
- 不同请求体或不同资源地址可以并发执行。
- 请求失败、取消或超时后在途锁必须释放。
- 管理系统新旧 HTTP 客户端与商户系统客户端均通过治理门禁、类型检查和构建。
- P0/P1 后端回归至少覆盖成功、重复请求、非法状态、并发冲突、超时未知和敏感日志。
- 异步导出回归至少覆盖重复任务提交、分页读取、租约冲突、失败重试、跨账号下载拒绝和文件过期。

## 5. 普通风控导入结果

- 普通风控配置导入按整批事务执行；任一行失败时成功数为零，不能显示部分成功或建议仅重传错误行。
- 原业务失败码保持不变；结构化结果可附带 `batchNo`、`totalCount`、`rolledBack`、错误行数和最多五条脱敏摘要。
- 文件总行数与校验错误行数分别展示；校验通过但随事务回滚的行仍属于未导入。
- 完整失败文件从当前导入账号专属接口下载，复用具体功能的导入权限；页面不得用有限摘要伪造完整报告。
- 服务端只流式输出行号和脱敏原因，不返回导入原始行；批次创建账号使用稳定账号 ID 绑定，不按显示名称授权。
- `REVIEW` 不再作为配置选项；历史复核值只作只读兼容，新配置默认使用可执行的通过或拒绝动作。
